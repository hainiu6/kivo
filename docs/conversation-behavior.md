# 已读状态与会话管理

Kivo v1.11.0 更新了客服收件箱与网页聊天窗口。

## 已读 / 未读

后台发出的文字、图片、表情及自动回复旁显示「未读 / 已读」。访客只有打开会话窗、网站页面在前台并看到对应消息，才会上报已读。仅加载历史或在后台收到消息不会标为已读。图片加载完成后也会检查可见范围。

已读时间保存在数据库，刷新后台和升级后保留。多人或多个页面打开同一会话时，任一页面看到消息即可标为已读；已读状态不会退回未读。

客户端 API 同样支持 `POST /api/client/v1/read` 和 `visitor:read` 实时事件，详见 [客户端文档](client-api.md)。旧版客户端未上报时保持未读。

## 同一浏览器复用会话

网页嵌入代码无需修改。同一网站来源、同一浏览器、同一站点 ID 使用固定的访客凭证，页面地址与 Session 显示名称不再参与分配会话；支持首次同时打开多个页面。旧的浏览器凭证会尽可能复用。

历史已存在的重复会话保留原记录，不自动混合不同凭证的历史。此修复适用于升级后重新加载的网页；打开旧页面的用户需刷新以载入新 widget.js。正常浏览器存储需要可用，隐私窗口 / 清除网站存储属于新的浏览器身份；不同来源的网页存储独立。

Session 名称只是显示资料。同浏览器的不同名称会共用匿名会话；要按登录账号隔离或跨设备恢复同一用户，请使用 [签名身份模式](php-integration.md)，该模式继续按站点与用户 ID 关联历史。

## 离线自动结束与排序

- 在线访客排在离线访客前面；各组按最近消息时间排序，并在上线 / 离线时即时调整。
- 最后一个页面或客户端连接离线后，持续满 10 分钟自动结束会话；后台每 30 秒检查一次。仍有其他页面在线时不会计时结束。
- 自动结束保留全部历史和图片；再次上线自动恢复自动结束的会话。手动结束的会话保持原有行为，新消息可重新打开。
- 服务重启后，以连接重新建立的情况判断在线；原本在线的会话从重启时开始计时，已经离线的会话保留原计时。

## 消息显示稳定性

消息更新、图片加载、已读变化与重新连接时复用原消息节点，避免重建全部图片、表情及聊天内容。后台返回当前会话时保留已显示记录和未发送草稿，再核对服务器历史；选中的会话再次点击时直接聚焦输入框。

## 升级

在客服服务器执行，完成后刷新客服后台及接入网页：

```bash
bash /opt/kivo/scripts/upgrade.sh
```
